# Business Modülü

İşletme kaydı, onay, belge yönetimi, konum ve sektör yönetimi.

:::warning Diyagramlar KAVRAMSAL — kodun bugünkü hâli değildir

Bu sayfadaki sınıf/sıra diyagramları modülün ilk tasarımını gösterir ve koddan **üretilmez**;
sapmayı yakalayan bir test de yoktur. Bilinen farklar:

- **API katmanı ASP.NET Minimal API'dir** (`MapGet`/`MapPost` → `bus.InvokeAsync`).
  `[WolverinePost]`/`[WolverineGet]` attribute'leri kodun **hiçbir yerinde kullanılmaz**;
  diyagramlardaki `POST`/`GET` etiketleri yalnız HTTP fiilini gösterir.
- **Enum'lar SmartEnum'dur** (`Name` İngilizce = serialize, `Slug` Türkçe = arayüz).
  Diyagramlardaki `MAZERETLI`, `ONAY_BEKLIYOR` gibi büyük harfli Türkçe değerler kodda
  bulunmaz.
- **Denetim aktörleri kimlik taşır, ad değil** (#139): `MarkedBy` → `MarkedById` (`Guid`).
  Ad okuma anında `UserNameView`'dan çözülür.
- Kiracı damgası, kapsam guard'ları ve onay zincirlerinin bugünkü hâli diyagramlarda yoktur.

Bir davranışın **bugünkü** kuralı için sırasıyla: `CLAUDE.md` → ilgili ADR →
[İş Kuralları](../architecture/business-rules.md) / [İzin Matrisi](../actors/permissions.md) →
kilitleyen test.
:::

## Sequence Diagrams

### İşletme Kendi Kaydını Açma (SelfRegisterBusiness)

```plantuml
@startuml BRASequenceDiagram
autonumber

actor "İşletme Yetkilisi" as BusRep
actor "Kurum Yönetimi" as InstAdmin
participant "Web UI" as UI
participant "MESNET.Business.Api\nBusinessEndpoints" as API
participant "MESNET.Business.Application\nHandlers" as Handler #LightBlue
participant "Marten\nIDocumentSession" as Marten #LightGreen
participant "RabbitMQ\n(Wolverine Transport)" as MessageBroker #Orange
database "business schema" as DB

== 1. İşletme Kendi Kaydını Açma ==

BusRep -> UI: İşletme kayıt formunu doldur
UI -> API: POST /api/business/self-register
API -> Handler: Handle(SelfRegisterBusiness command)
Handler -> Marten: session.Store(business)\n(status = ONAY_BEKLIYOR)
Marten -> DB: INSERT (JSONB)
DB --> Marten: Success

Handler --> API: BusinessApprovalRequested (cascading)
API --> UI: Success
UI --> BusRep: "Kaydınız alındı.\nKurum onayı bekleniyor."

Handler -> MessageBroker: PublishAsync<BusinessApprovalRequested>

note right of Handler
  İşletme kendi kaydını açtığında:
  - Status = ONAY_BEKLIYOR
  - Sisteme üye olamaz (login yapamaz)
  - Kurum onaylamadan aktif olmaz
end note

== 2. Kurum Bilgilendirilir ==

MessageBroker ->> InstAdmin: Bildirim: "Yeni işletme kaydı onay bekliyor"

== 3a. Kurum Onaylarsa ==

InstAdmin -> UI: İşletme kaydını incele ve onayla
UI -> API: POST /api/business/{id}/approve
API -> Handler: Handle(ApproveBusiness command)
Handler -> Marten: business.Status = AKTİF\nsession.Store(business)
Marten -> DB: UPDATE (JSONB)
DB --> Marten: Success

Handler --> API: BusinessApproved (cascading)
API --> UI: Success
UI --> InstAdmin: "İşletme kaydı onaylandı"

Handler -> MessageBroker: PublishAsync<BusinessApproved>

note right of Handler
  Onay sonrası:
  - Status = AKTİF
  - İşletme sisteme giriş yapabilir
  - Stajyer kabul edebilir
  - Tüm durum geçişleri event sourcing
    ile kayıt altında
end note

== 3b. Kurum Reddederse ==

InstAdmin -> UI: İşletme kaydını incele ve reddet
UI -> API: POST /api/business/{id}/reject
API -> Handler: Handle(RejectBusiness command)
Handler -> Marten: business.Status = REDDEDİLDİ\nsession.Store(business)
Marten -> DB: UPDATE (JSONB)
DB --> Marten: Success

Handler --> API: BusinessRejected (cascading)
API --> UI: Success
UI --> InstAdmin: "İşletme kaydı reddedildi"

Handler -> MessageBroker: PublishAsync<BusinessRejected>

note right of Handler
  Wolverine Middleware Pipeline:
  - FluentValidation
  - AutoApplyTransactions (Marten)
  - Durable Local Queues

  Hybrid Storage:
  - İşletme bilgileri → Document (JSONB)
  - Durum geçişleri → Event Sourcing
  - Geçmiş veriler kaybolmaz
end note

@enduml
```

### İşletme Bilgisi Düzenleme (EditBusinessInfo)

```plantuml
@startuml EBISequenceDiagram
autonumber

actor "İşletme Yetkilisi" as BusRep
participant "Web UI" as UI
participant "MESNET.Business.Api\nBusinessEndpoints" as API
participant "MESNET.Business.Application\nUpdateBusinessInfoHandler" as Handler #LightBlue
participant "Marten\nIDocumentSession" as Marten #LightGreen
participant "RabbitMQ\n(Wolverine Transport)" as MessageBroker #Orange
participant "Wolverine Handler\nInstitution.Application" as InstHandler #LightBlue
database "business schema" as DB

' Mevcut bilgileri getirme (Query)
BusRep -> UI: İş yeri bilgilerini düzenleme sayfası açılır
UI -> API: GET /api/business/{businessId}
API -> Handler: Handle(GetBusinessInfoQuery)
Handler -> Marten: session.LoadAsync<Business>(id)
Marten -> DB: SELECT (JSONB)
DB --> Marten: Business document
Marten --> Handler: Business entity
Handler --> API: BusinessInfoDTO
API --> UI: BusinessInfoDTO
UI --> BusRep: Mevcut bilgiler gösterilir

' Bilgileri güncelleme (Command)
BusRep -> UI: Güncellenmiş bilgileri gönder
UI -> API: PUT /api/business/{businessId}
API -> Handler: Handle(UpdateBusinessInfo command)
Handler -> Marten: session.Store(updatedBusiness)
Marten -> DB: UPDATE (JSONB)
DB --> Marten: Success

' Cascading message — handler return değeri otomatik publish edilir
Handler --> API: BusinessUpdated (cascading)
API --> UI: Success
UI --> BusRep: "Bilgiler güncellendi" mesajı

' Asenkron event dağıtımı
Handler -> MessageBroker: PublishAsync<BusinessUpdated>
MessageBroker ->> InstHandler: Handle(BusinessUpdated)

note right of Handler
  Wolverine Middleware Pipeline:
  - FluentValidation
  - Logging
  - AutoApplyTransactions (Marten)
  - Durable Local Queues
end note

@enduml
```
